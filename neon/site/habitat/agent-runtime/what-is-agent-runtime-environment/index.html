What is a Model Router?

A model router implements provider adapters behind a common interface for intelligent model selection and capability-based routing.

Model Fabric Architecture

The router presents a unified interface to multiple providers:

  • OpenAI: GPT-4, GPT-3.5 models
  • Qwen: Specialized for technical tasks
  • Kimi: Multilingual and technical capabilities
  • MiniMax: Chinese language optimization
  • Local: Self-hosted and on-premise models
  • Custom OpenAI-compatible: Any OpenAI-compatible API

Routing Policies

Model selection follows intent-based routing strategies:

  • AUTO: Automatic selection based on task requirements
  • QUALITY: Prioritizes highest-performing models
  • SPEED: Optimizes for response latency
  • COST: Minimizes token usage and pricing
  • PRIVACY: Prefers private/local models for sensitive contexts
  • LOCAL: Forces local model usage when available
  • BALANCED: Balances multiple optimization criteria

Routing Decisions

Model selection considers multiple factors:

  • Task capability: Required skills and expertise
  • Privacy requirements: Sensitive vs. public data handling
  • Hardware constraints: VRAM and processing capabilities
  • Context window size: Required token capacity for the task
  • Quality expectations: Historical performance metrics

Provider Adapters

Each provider implements standardized interfaces:

  • Consistent API contracts: Unified method signatures
  • Capability discovery: Available functions and models
  • Error handling: Standardized failure responses
  • Performance metrics: Latency, throughput, and quality data

Routing Persistence

Model invocations are recorded for analysis and optimization:

  • Provider and model identification
  • Capability decision rationale
  • Input/output token counts
  • Latency measurements
  • Cost tracking
  • Fallback information for failed invocations
  • Truth state documentation
  • Correlation IDs for tracing
