What is an AI Agent?

An AI agent is a software system that can plan and execute engineering tasks using models, repository context, tools, permissions, tests and controlled execution.

Core Architecture

The agent runtime provides the foundational execution contract:

  • Context access: Repository analysis and project understanding
  • Tool calling: Filesystem, shell, Git, browser, database and MCP operations
  • Execution scope: Workspace boundaries and permission validation
  • Verification integration: Build, test, security and artifact validation

Execution Layers

Agents operate through a controlled loop:

  1. Understand: Goal analysis, repository context and policy interpretation
  2. Plan: Validated task graph creation with dependencies and capabilities
  3. Route: Capability-based model selection with privacy and context awareness
  4. Execute: Scoped tool usage with real-time approval when needed
  5. Verify: Independent acceptance gates determine completion
  6. Learn: Memory and skills update for future tasks

Identity and Lifecycle

Each agent maintains its own:

  • Context state: Working memory and session history
  • Model identity: Provider and capability profile
  • Budget controls: Resource usage limits and approval thresholds
  • Workspace isolation: Dedicated execution environment
  • Permission set: Allowed tool categories and action boundaries
  • Lifecycle state: SPAWNED → READY → RUNNING → COMPLETED/FAILED

Governance Model

Agents follow ALLOW/ASK/DENY governance:

  • ALLOW: Scoped read/write operations within project boundaries
  • ASK: External network access and irreversible actions require explicit approval
  • DENY: Unknown or potentially destructive operations are blocked

Verification Integration

An agent’s completion requires independent verification:

  • Build processes must pass automated checks
  • Tests must achieve coverage targets
  • Security scans must identify no critical issues
  • Artifacts must be validated and attested
  • Model output alone does not determine completion

Key Differentiators

  • Sovereign execution: Operates under your control and policies
  • Local-first execution: Prefers private models when context demands it
  • Evidence-led completion: Verification determines success, not model claims
  • Controlled tool access: Every operation passes policy and approval gates
