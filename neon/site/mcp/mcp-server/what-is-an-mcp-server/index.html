What is an MCP Server?

An MCP (Model Context Protocol) server is a capability declaration and transport layer for connecting AI applications with external tools and data sources.

Server States

MCP servers operate in defined health states:

  • UNAVAILABLE: Not configured or inaccessible
  • UNKNOWN: Not yet tested or verified
  • DEGRADED: Partially functional with limitations
  • HEALTHY: Fully operational and tested

A server remains UNAVAILABLE, UNKNOWN, or DEGRADED until an actual transport adapter, health check, and authenticated execution path exist.

Server Components

A functional MCP server requires:

  • Transport layer: stdio, HTTP, or custom protocol support
  • Capability catalog: Complete list of available tools and resources
  • Authentication system: Token, certificate, or API key validation
  • Authorization mechanism: Permission boundaries and scope control
  • Health monitoring: Connectivity and functionality checks
  • Error handling: Graceful failure and recovery protocols

Server Lifecycle

MCP server operations follow this sequence:

  1. Connect: Establish transport and authenticate
  2. Refresh: Validate capabilities and test connections
  3. Enable/Disable: Toggle availability based on policy
  4. Test connection: Verify functionality before use
  5. Health monitoring: Continuous status tracking

Transport Types

Supported transport protocols:

  • Standard I/O (stdio): Command-line interface communication
  • HTTP/S: Web-based protocol for remote connections
  • gRPC: High-performance binary protocol
  • Custom adapters: Specialized integrations for unique systems

Server Management

Administrative operations include:

  • Tool inventory: Complete catalog of exported capabilities
  • Permission mapping: Alignment with agent authorization rules
  • Last-used tracking: Activity monitoring and cleanup
  • Audit trail: Complete connection and usage history
